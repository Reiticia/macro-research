# 宏观事件双时区显示

宏观事件默认同时展示两个时钟，也可在 **设置 → 事件时间显示** 中选择只显示其中一个：

- **设备本地**：当前设备系统时区，不固定为北京时间。
- **地区当地**：事件所属国家／地区的宏观数据发布参考时区。

例如，`2026-11-04T13:30:00Z` 在上海设备上显示本地 `21:30 (UTC+08:00)`，纽约为 `08:30 (UTC-05:00)`。夏季纽约自动使用 `UTC-04:00`，不能全年减 13 小时；美国和欧洲夏令时切换日期也分别计算。

## 显示设置

- **本地时间**：只显示设备系统时区的时间。
- **当地时间**：只显示事件所属国家／地区参考时区的时间。
- **本地时间与当地时间**：同一行显示两个时钟（默认，兼容原有显示）。

选择后立即作用于全部宏观事件页面，持久保存，重启和切换数据源后保留；不需要网络请求。仅当地时间模式下，历史和详情仍显示当地完整日期；单日列表遇到地区跨日也会显示当地日期，避免把它误认为设备日历日期。当地时区未知时明确提示，不静默改用本地时间。

## 范围与日期

首页下一事件、日历周／月／单日卡片、历史、关注、事件详情及分析页共用 `EventTimes`。默认双时间模式合并为一行紧凑显示，例如「本地 21:30 (UTC+08:00) | 纽约 08:30 (UTC-05:00)」；过长时可横向滑动，不换行或截断。地区时间与设备时间同日时不重复日期，跨日或跨年则保留地区完整日期；跨多天列表和详情的设备时间同样带完整日期，单日列表设备日期由页头提供。UTC 偏移按事件时刻而非今天计算，夏令时回拨出现两次的相同时分也可区分。

日历请求范围、日期条、首页今日和历史同步仍按设备系统时区计算，不改变事件的存储瞬时、排序、倒计时、关注 ID 或后端接口。美股财报的纽约日期和盘前／盘后规则不变。

## 地区映射

主要地区：美国 → `America/New_York`，欧元区 → `Europe/Berlin`（中欧／法兰克福），中国 → `Asia/Shanghai`（北京时间），日本 → `Asia/Tokyo`，英国 → `Europe/London`。同时支持日历源常见的其他国家及 ISO 代码，例如加拿大 → `America/Toronto`（渥太华同区）、澳大利亚 → `Australia/Sydney`（堪培拉同区）、印度 → `Asia/Kolkata`。

数据源只有国家／地区，没有具体演讲地点。因此，多时区国家展示的是明确的参考城市时区，不代表每一场活动实际所在地；事件详情有这一说明。未知地区、全球事件以及不受支持的标签显示「时区未知」，不会从美元等货币推测国家，也不会用设备时区冒充地区时区。

`timeExact=false` 的日期型事件显示「时间待定」，不把数据源的日期占位值当作零点公布；跨日历史列表仍保留原有日期。时间损坏或无法解析时显示「时间不可用」。

## 实现与测试

- `ui/common/EventTimezones.kt`：地区映射、同一瞬时转换、显式 UTC 偏移格式化。
- `ui/common/EventTimes.kt`：三语共享组件，通过应用级 `LocalEventTimeDisplay` 读取偏好，无时分截断；`CalendarPreferences` 保存显示选择。
- `EventTimeDisplayUiTest`：验证选项持久化、即时切换、原始日期保留、未知地区及日期型事件（需设备执行）。
- `EventTimezonesTest`：覆盖冬夏偏移、美国春季跳时／秋季重复小时、美欧不同切换日期、跨日跨年、南半球季节与半小时时区、未知国家、日期型与损坏时间，以及非中国设备时区、三种显示模式、仅当地时间的日期保留。

这是展示层更新，无数据库迁移，也不需要更新后端。
