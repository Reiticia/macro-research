# 后端公开日历事件入库去重

## 判定规则

适用于 TradingView、BiQuote、Forex Factory 的公开日历记录；先检查已知 `(provider, providerId)` 及其历史别名，再做名称匹配。历史别名只是候选线索；不同来源或不同 occurrence ID 的写入必须重新验证，不能绕过来源专属否决、统计期及阶段冲突。

名称匹配必须同时满足：

1. 国家字段相同。
2. 两边 `timeExact=true`，且 UTC 公布时刻完全相同，不只比较日期或显示到分钟的时间。
3. 满足任一名称条件：
   - 英文原名先转小写，再去掉空格/符号等所有非 `a-z`、`0-9` 字符，得到非空且一致的键。例如 `Core CPI (YoY)` 与 `core-cpi_yoy` 都是 `corecpiyoy`。
   - 有已逐条核实的来源映射，例如密歇根初值和 Ivey 季调／未季调映射，并通过相应统计月份等校验。

中文译名仅供显示，不能单独授权身份匹配，包括来自人工或 AI 审核的翻译缓存。显示翻译的容错策略不得决定 Actual 写入目标。

`CPI m/m` 的新严格键为 `cpimm`，不是 `cpimom`。原有**已逐条验证**的跨源同义表仍单独保留，不扩大或猜测别名；只有跨来源、时刻精确、候选唯一且当前批次没有多个不同规范名造成歧义时才使用该回退规则。空规范键不能让不同中文/符号标题被误合并。

同名的不同国家、不同月份、不同精确时刻，以及未知/不精确时刻，不因名称相似而合并。身份明确的同一上游 ID 仍可按原有规则更新其日程，不把正常改期当成新指标。

## 写入与数据保护

- 首次见到事件正常入库；后续同名同次公布的唯一匹配复用原数据库事件 ID，包括同一批次内的重复行、同源上游 ID 更换、大小写/空格/符号变化；英文不同且只有相同中文译名时不会归并。
- 使用 SQLite `BEGIN IMMEDIATE` 将查重与写入串行化，防止启动同步、周期同步、公布值轮询并发检查后各插一份；跨源检查同时考虑库中记录和当前批次尚未写入的事件，避免先写初值再看到终值冲突。
- 公布值按原有来源优先级更新：TradingView > BiQuote > Forex Factory。备用源可在单位维度及缩放兼容时仅填补缺失 Actual，保留目标预期、前值和显示单位，继承真实数值来源；不能用另一个值覆盖已有主源 Actual；不以行情伪造公布值，也不因同名合并让已有可靠值退回缺失。
- 同优先级、同批重复记录若给出互相冲突的非空 Actual，不按数组顺序猜选：保留已有可靠数值，没有旧值时明确缺失，并等待后续无歧义响应；公布轮询遇冲突也不假报已公布。
- 保留事件 ID、观察历史、分析/行情引用、已选市场标的与客户端关注关系。更新不会把 Watching/Completed 等状态重置成 Scheduled，也不绕过 historical 的既有数值保护。
- 认证 Trading Economics 历史导入仍独立保存，不参与公共源名称去重。
- 入库、普通监控、快速轮询和备用周历补值共用确定性校验；轮询不依赖翻译缓存，不调用翻译或 Jev。未知映射继续等待主源，AI 不可用不会改变匹配标准。
- 裸 K/M/B/T 只代表缩放，不是任意维度的通配符；仅已核实的非农定义可确认 K 与 K jobs 的人数维度。未知单位、不同币种和 Decimal 溢出均跳过。来源升级若不能转换旧 Actual，保留原记录，不重命名后继续套用旧预期／前值。
- 仅已核实的月度指标可将来源统计期规范到月份，普通周度／日度指标的不同日期不能因此被视为同次公布。

## 上游身份别名与迁移

迁移 `027_event_provider_aliases.sql` 新建 `event_provider_alias`，将原有 `(provider, providerId)` 绑定到事件 ID，并在每次已确认的归并/来源升级时同时保留旧身份和新身份。

`GET /api/v1/events/by-provider?provider=...&provider_id=...` 继续沿用原鉴权和 JSON 契约，可通过旧 ID 查到同一事件；返回当前规范来源的信息，`id` 不变。不需要客户端协议/Room 迁移，也不改变配置模板或增加必填配置。

迁移只新增映射，不删除/重建事件，也不自动清理旧重复。升级部署前照常备份数据库，启动后自动执行待应用迁移；029 增加来源元数据，030 增加兼容旧 Z／+00:00 时间的公布查询表达式索引。

## 旧重复与歧义

- 如果当前库有多个可匹配的事件，且新上游 ID 尚未绑定，跳过这一条并记录 `ambiguous calendar identity; skipping new upstream ID`，避免猜选所有者或新增第三条；同批其他明确事件继续同步。
- 当前来源自己的 ID 可正常更新；旧别名指向的跨来源／其他 occurrence ID 记录须重新验证。旧重复不会被自动拼接、隐藏或删除，已核实的不同来源旧 ID 可分别接收同次 Actual；同来源多候选仍拒绝补值。
- `save_events*` 返回成功写入/复用的 ID；一条歧义记录被跳过时不返回占位 ID。因此公布轮询仅让**实际被更新且具有 Actual 的 Watching 记录**进入 Released，不能把另一条同名旧记录在 Actual 缺失时误标为已公布或重复推送。
- 需要清理已经存在的重复时，先单独核对原始英文名、时间精度、来源 ID、数值和关联记录，设计保留 ID/别名及关联迁移。不要直接按中文名或规范英文名执行批量 DELETE。

`backend/tests/event_deduplication.rs` 覆盖英文规则、相同中文不得归并、月份/国家/纳秒/精度隔离、同批去重、ID 更换、旧 ID 查询、数值/状态/观察保护、旧歧义跳过、Forex Factory 等价时间表示、v26→v27 迁移和并发写入。

`backend/tests/unified_backend.rs` 及 `support/release_identity.rs`、`support/release_safety.rs` 覆盖带鉴权的旧/新 provider ID 查询、拒绝中文缓存授权公布、旧 ID 通知、反向错误别名、批次阶段冲突、统计期冲突、单位转换及溢出、备用源来源链、来源升级失败保护和表达式索引查询计划。全部使用合成数据、内存/临时测试库与本地 mock，不访问生产数据库或外部模型。
