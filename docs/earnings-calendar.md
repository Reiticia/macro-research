# 美股财报日历

“日历”页默认使用一周日期条与所选日期的内嵌日程列表，右上角提供整月月历入口；两种视图均支持“全部 / 财报 / 经济事件”筛选。直连与后端模式均支持，不新增底部导航、不改变宏观事件、关注、推送或 AI 分析的数据模型。

## 数据与边界

- **Nasdaq 主源**：`GET https://api.nasdaq.com/api/calendar/earnings?date=YYYY-MM-DD`。按日读取公司、股票代码、财季结束月份、美东盘前/盘后/未知、EPS 预期、分析师数量、市值、去年同期 EPS；部分历史记录另有已公布 EPS 和来源自带的超预期比例。
- **TradingView 补充与备用源**：`POST https://scanner.tradingview.com/america/scan`。Nasdaq 成功时按准确股票代码 + `is_primary` 查下一次日期、下一期 EPS / 营收预期；同名结果不唯一时不合并，不猜交易所或股份类别别名。Nasdaq 失败且无缓存时，按美东单日时间区间查询备用日历；时间一律未知、财季留空。
- 两者无需上游 API Key。它们是网站内部端点，没有公开稳定性或完整覆盖承诺，可能限流、变更、返回空字段；免鉴权不表示授权商用再分发。
- 以 **America/New_York 的日期**选日与分组，不能按设备时区把整条“盘后”事件移动到另一日。来源更新时间以设备时区显示。秒级时间戳只用于提取美东日期，不视为公司确认的精确发布时间。
- TradingView 的字段是 **下一期快照**，分开展示，不写入 Nasdaq 的季度预期字段。日期相同也不能证明财季、EPS 调整口径或财务币种一致；报价币种不是财报币种，营收不擅自添加美元符号。
- 不给过去日期或 Nasdaq 已有实际 EPS 的记录补“下一期预测”，避免把正常的下一财季当成日期冲突。未来未披露记录的日期不一致时展示冲突，不覆盖 Nasdaq 日期。
- 首版不提供公司确认状态、电话会时间、分钟级提醒、关注/改期通知、AI 分析、完整历史财务报表或秒级公布值监控。界面中所有日程均标注未获公司确认。

## 界面

- 默认进入周列表：周一起始的七日日期条、前后周切换与今天跳转，直接展示所选日期的日程列表，不必先点月格。默认只加载七日数据，不请求隐藏的整月数据。
- 右上角月历按钮进入周日起始的六周月视图，左上角返回按钮或系统返回键回到原周列表，恢复原选中日期及类型/重要性筛选。月视图支持前后月、今天和日期选择；跨月日期可点击。日期格显示最多四个财报预览位置（公司 Logo 或溢出数量），彩色圆点与数量表示经济事件；小屏和大字体时月格区域可滚动，按可见周加载 Logo。
- 月视图点击日期打开当日日程底部面板；周视图点击日期直接切换内嵌列表。列表跟随“全部 / 财报 / 经济事件”筛选；支持事件/公司/股票搜索、经济事件重要性多选、财报盘前/盘后/未知筛选。经济事件卡片仍可进入原有详情页，财报卡片保留 EPS、预测、来源与冲突信息。
- 默认今天指美东今天。财报始终按美东日期分格，经济事件按设备时区分格并显示实际时间；页面和日列表都明确标注两种时区口径，不给财报捏造精确发布时间。
- 两种视图先读本地财报快照，按单日接口逐步更新，优先当前选中日期，不并发轰炸上游；切周/月、返回周列表、切数据源或隐藏某类数据会取消对应旧请求并丢弃迟到结果。经济事件用单次可见范围查询（周列表 7 天、月历 42 天），不逐日重复请求；国家和重要性筛选同时作用于月格与日列表。
- 加载中显示省略点，失败/旧缓存日期显示警示，超出财报支持范围显示范围提示；未加载或请求失败不当作成功空日。认证失败、旧后端不支持或连续故障会停止余下月请求，避免请求风暴。Nasdaq 与 TradingView 分别保留更新时间；展示来源故障、较旧缓存、日期冲突和冷却提示，预测缺失显示破折号。

## 财报页面跳转

财报卡片（周列表、月历单日面板、独立列表）与个股详情提供「财报公布页 · Nasdaq / TradingView」。点击后通过系统浏览器打开对应公司的公开财报汇总页：Nasdaq 记录使用准确股票代码构造 `/market-activity/stocks/{symbol}/earnings`；TradingView 备用记录仅在来源 ticker 的交易所受支持且代码与该事件完全一致时构造 `/symbols/{exchange}-{symbol}/financials-earnings/`，不猜交易所、股份类别别名或公司域名。非法/缺失标识、未知来源时禁用入口；无法启动浏览器时在原页面提示。

当前上游不提供具体财季的公司 IR 公告链接。这些页面可能展示最新或其他财季，**不是所选日期/财季的官方公告原文**，也不证明财报已公布；界面明确提示，未披露记录同样可查看预期。第三方页面可能改版、限制访问或没有该代码，不保证可用。两种数据模式均只在用户点击时显式外跳，不创建 WebView、不抓取页面、不传后端令牌或设备绑定头、不触发 AI；不改变后端数据失败时禁止静默直连的规则。无需后端升级或数据库迁移。

## 财报收藏与当前股价

- 周日程、月历日期展开、财报列表与个股详情的星标可收藏/取消收藏**本次财报事件**。从首页“已关注事件”进入同一收藏列表，财报与宏观事件分组，点击财报的“查看对应股价”重新进入详情。收藏不是滚动的股票订阅，不新增推送或后台抓取。
- Room 10 → 11 新增 `earnings_favorite`，按数据模式/后端地址哈希、纽约日期、准确股票代码唯一保存财报快照；重复收藏幂等，支持重启后恢复，日历缓存清理不会删除收藏。收藏快照不保证持续更新或跟随下一财季/改期；重新收藏可更新快照。切换模式或后端时只展示该来源的收藏，切回恢复，地址和凭据不写入收藏键。原有宏观缓存/关注/分析的清理规则不变，迁移保留已有数据。
- 详情顶部单独显示**当前股价**，与所选财报日期无关；只在详情可见且应用前台时立即读取并每 **5 秒**刷新，不重叠请求，离开/后台取消。完成的历史财报也可读当前价；它不会补写或冒充下方公布后 60 分钟采样。原有历史采样仍按 15 秒、原检测窗口读取。
- 当前价使用受保护的 `GET /api/v1/earnings/quote/{symbol}`，能力标记 `earningsQuote`。响应 `{symbol, price: string, currency: string|null, timestamp, fetchedAt, provider: "yahoo", timestampBasis: "provider_quote"|"minute_bar_close", stale: boolean}`；`timestamp` 是真实报价/已收盘分钟结束时间，`fetchedAt` 仅表示后端获取时间。HTTP `no-store`，沿用 Key/设备绑定，非法代码返回 400，旧后端/鉴权/限流明确提示并停止自动重试，网络故障保留旧显示并标注失败。
- 后端**仅内存缓存**：股票代码为键，最多 128 项，成功和失败尝试均缓存 5 秒；同代码并发合并、不同代码独立，缓存满时淘汰最久未使用且无请求持有的项。每次上游最长 8 秒，失败最多返回最近成功获取后 120 秒内的旧值并标 `stale`，否则返回错误；重启不保留，不写 SQLite/磁盘，不创建财报采样任务，无用户页面请求时不轮询当前价。
- 复用宏观/财报采样的 Yahoo 实例、显式代理路由、节流与 403/429 冷却。保留股票代码、EQUITY 类型、有效数值、币种和未来时间校验。当前价允许展示不足 7 天的最近已知价格，以便闭市时显示最后报价；旧于 90 秒统一标“较旧报价”，不将获取时间伪装成报价时间。分钟价标明非逐笔报价，Yahoo 可能延迟，5 秒刷新不意味着交易所逐笔实时。
- 实时股价需更新后端并使用后端模式；直连模式明确提示，不隐式直连 Yahoo。两种模式均可收藏。无需新增后端配置或迁移；Android 需 schema 11。

## 公司 Logo

财报卡片左侧按准确的美股代码加载公司 Logo。图片源为免鉴权的 FMP 静态 PNG：`https://images.financialmodelingprep.com/symbol/AAPL.png`，不调用其需要 API Key 的财务接口、不猜公司域名、不改变 Nasdaq / TradingView 财报字段。股份类别按原代码请求（如 `BRK.B`），没有图片时不猜别名。

直连模式使用数据源代理访问公开图片；后端模式仅访问自建后端的受保护图片转发接口，**不静默直连 CDN**。公开图片请求不携带后端 Key 或设备标识。后端通过网络源名 `earnings_logo` 选择代理，旧配置需要代理时自行将它加入 `[network].proxied`。

仅对可见卡片异步加载，不等待图片才显示财报。加载中、404、旧后端不支持、解码失败或网络异常时显示股票代码前两位占位；不会清空日历、触发财报告警或影响数值。切换数据源/后端地址会重建图片状态，丢弃旧来源的迟到结果。

客户端内存缓存按模式和地址隔离，最多 64 项。后端不使用 Logo 内存缓存或 SQLite：图片下载后保存为独立 PNG 文件（如 `data/earnings-logos/logo-AAPL.png`），同名 `.json` 保存过期时间、是否有图片和 LRU 访问时间；最多 128 项，超限同时删除最久未访问项的 PNG 与元数据，每次命中从文件读取，重启后继续复用。两端成功缓存 24 小时、失败缓存 5 分钟，刷新失败保留旧图；相同请求合并。直连还复用现有 OkHttp 磁盘缓存策略。403/429 按 Retry-After 冷却，后端冷却截止时间写入目录内的 `cooldown.json`，重启不会清除冷却。仅允许固定图片主机和经过校验的股票代码，不接受任意图片 URL；单图不超过 256 KiB、PNG 尺寸不超过 1024×1024，界面缩小解码至约 256 像素以内。Logo 属于辅助识别信息，可能缺失、过期，商标权归原持有人。

后端通过可选配置指定图片目录，旧配置未填写时使用默认值：

```toml
[earnings_logo]
cache_dir = "data/earnings-logos"
```

相对路径以 `config.toml` 所在目录为基准，也可指定绝对路径；目录自动创建，需确保服务进程有读写权限。PNG 和元数据先写同目录临时文件，再原子替换，避免中断下载覆盖旧图；读取时校验尺寸与大小，损坏/丢失文件按缓存未命中处理。目录由单个服务进程独占，不应由多实例同时写入。该目录是可删除重建的缓存，不随 SQLite 数据库备份；需要保留时单独备份目录。无需新增数据库迁移或第三方图片加载依赖。修改配置模板后，自动部署仍按原有基线规则处理，旧私人配置不自动改写。

## 缓存、请求与故障

- 支持范围：美东今天之前 120 天至之后 60 天（含边界），不承诺上游在整个范围都有数据。
- 两端使用相同新鲜度策略：过去 7 天及今天 1 小时、未来 7 天 6 小时、其他日期 24 小时；手动刷新可绕过新鲜度，但每个日历缓存键的尝试至少间隔 60 秒。
- 每个上游请求间隔至少 1 秒，403/429 进入冷却，读取 `Retry-After` 秒数或 HTTP 日期，默认 300 秒，冷却范围 60 秒至 24 小时；不绕过反爬或关闭证书验证。
- Nasdaq 必须返回成功状态、正确日期和合法行结构，才能替换整个单日快照。明确的空数组/空 rows 是空日历；缺字段、错误状态、错日期或重复代码不是空日历。
- TradingView 单次最多请求 2000 行；若 `totalCount` 与返回行数不符、交易所代码重复，或备用日历返回其他日期，视为失败并提示，不把第一页或错误日期当完整结果。
- Nasdaq 失败时已有 Nasdaq 缓存优先保留，不用较弱备用数据覆盖；仅有 TradingView 备用缓存时，仍允许健康的 TradingView 更新它。两源失败且没有缓存时返回错误，不伪造空成功。失败不推进最后成功更新时间。
- Android 使用独立 Room 表，按直连/后端地址哈希隔离缓存；不存访问密钥或设备标识。模式/地址变更取消旧请求并丢弃迟到结果。后端不可达、未授权或旧版不支持时，不静默改用直连。
- Android 复用“数据源网络”的可选代理，只向自建后端发送后端鉴权和设备绑定头。后端按 `[network].proxied` 中的 `nasdaq`、`tradingview` 分别选路；旧配置的显式列表如未含 `nasdaq`，需由管理员自行加入才能代理它。

## 后端 API 与运行

```http
GET /api/v1/earnings?date=2026-11-02
Authorization: Bearer <existing backend key>

GET /api/v1/earnings?date=2026-11-02&refresh=true
```

公司图片接口为 `GET /api/v1/earnings/logo/{symbol}`，使用相同 Bearer / 设备绑定鉴权；成功返回 `image/png` 与 `X-Content-Type-Options: nosniff`，图片不可用返回 404，非法代码返回 400。该接口只接受股票代码，不接受来源 URL；不经过财报同步锁。

`date` 为 `YYYY-MM-DD`，省略时使用美东今天。查询受现有鉴权保护、响应 `Cache-Control: no-store`；上游免鉴权不改变后端访问密钥要求。`/api/v1/meta` 的 capabilities 包含 `earnings` / `earningsLogos` / `earningsMarket`，API 协议版本仍为 1。

响应为单日对象（camelCase）：

```text
{ date, timezone, updatedAt, nasdaqUpdatedAt, tradingViewUpdatedAt,
  stale, warnings, events: [
    { symbol, name, source, session, fiscalQuarterEnding, epsForecast,
      analystCount, marketCap, actualEps, surprisePercent, lastYearEps,
      tradingView: { ticker, nextDate, nextEpsForecast, nextRevenueForecast,
                     quoteCurrency, dateConflict } | null }
  ] }
```

数值使用十进制字符串（分析师数量为整数），可空字段保持 null。`session` 为 `pre_market` / `after_hours` / `unknown`。警告码为 `nasdaq_unavailable`、`tradingview_unavailable`、`date_conflict`、`refresh_cooldown`；Android 本地刷新失败另用 `refresh_failed`。没有精确时刻或宏观事件 ID。

服务启动后独立后台任务每小时扫描今天至未来 60 天及过去 7 天，仅刷新到期日期，不阻塞 HTTP 启动。健康键为 `earnings_nasdaq` / `earnings_tradingview`，沿用现有来源健康与告警机制。

数据库升级：后端启动执行 `023_earnings_calendar.sql` 与 `024_earnings_stock_collection.sql`（Logo 仍为文件缓存，不存数据库）；Android Room 9 → 10 只新增独立财报快照表，保留宏观事件、关注和分析。发布/部署仍遵循项目原有流程；本功能不自动部署或改动本机私人配置。

## 财报公布后的个股行情采集

后端增加独立财报监测与行情任务，不需要 APP 发起请求才运行。客户端已增加对应股票的价格详情，复用事件页面的实际行情表与时间线交互风格；入口位于财报卡片的“查看对应股价”。

### 触发和时刻口径

- 约每 65 秒强制刷新纽约今天及昨天的财报，复用原有单日请求合并、至少 60 秒间隔及 403/429 冷却，不受日历一小时缓存新鲜度限制。
- 只接受校验通过的 Nasdaq 主源，同一纽约日期、准确股票代码的实际 EPS 从未公布变为已公布（包括实际值为 0）时创建任务。需要此前 5 分钟内见过该条未公布记录；日历写入、监测状态和任务创建同事务提交。历史记录、TradingView 下一期快照、旧缓存及机器人诊断均不能触发任务。
- `detectedAt` 是首次读到该次 EPS 变化的时间（在可选 TradingView 补充工作之前记录），不是公司确认的精确发布时间。公开接口可能延迟更新，因此是近分钟级检测，并不保证从公司发布瞬间开始完整捕获。
- 初次启动就已公布的记录标为 `already_reported`，长时间断线后才发现实际值标为 `missed_after_gap`，明确的财季冲突标为 `quarter_changed`，不会把旧财报当成新发布而启动当前价格采集。

### 60 分钟采样与恢复

- 每次触发固定采集 `detectedAt` 起 **60 分钟**；采样周期沿用 `[scheduler].market_poll_seconds`（默认 15 秒，最低 5 秒），按来源报价时间聚合为 UTC 分钟 OHLC。该 OHLC 是采样价格的开/高/低/收，不承诺等同交易所逐笔成交生成的完整分钟 K 线。
- 从 Yahoo 获取准确股票代码的 `EQUITY` 报价，使用 `includePrePost=true` 请求盘前/盘后数据。优先选择最新有效报价；只能取得分钟 K 线时，仅使用已收盘分钟的收盘价并以分钟结束时间记录，`timestampBasis` 区分 `provider_quote`、`minute_bar_close` 与混合采样 `mixed`。
- 已核查 BiQuote 的股票目录、报价和 OHLC：本次盘后 AAPL/NVDA 同名标的仅有陈旧数据，实时的 `NVDAUSDT` 不能直接替代正股，暂不切换主源。特别是报价 404 也可能表示数据过期，不能作为“标的不存在”的唯一依据；详见 [BiQuote 个股与盘前盘后核查](biquote-stock-data-source.md)。
- 不猜股份类别别名；例如来源若把请求的 `BRK.B` 返回成 `BRK-B`，会记录缺失，不把另一代码的价格混入。报价币种独立保存，不据此推断财报财务币种。
- 旧于 90 秒、未来时间、触发前、窗口结束后、股票代码/币种冲突、非正数或非有限数的报价都不写入；闭市或上游故障留下真实缺口，不用昨日收盘价或当前价格伪造历史点。
- 监测状态、起止时间及分钟数据保存在独立 SQLite 表，重启后续采原窗口剩余时间，不重置或延长 60 分钟；EPS 修订或重复刷新也不重启任务。过期任务不再请求新价格，`completed` 只表示窗口已结束，不代表数据完整。
- 个股与宏观 Yahoo 请求复用同一实例的节流与 403/429 冷却；每轮最多处理 32 个任务，按上次尝试时间公平轮换，同一股票在一轮内只请求一次。大量同时公布或上游限流时采样可能延迟，覆盖情况如实返回。单只股票取价失败不阻止其他股票采集，也不直接把整个行情源判定为断网。
- 财报行情独立于宏观事件的标识、分析、关注及推送，不改变已有事件流程；相关记录随数据库备份，保留 120 个纽约日期。新增迁移 `024_earnings_stock_collection.sql`，不新增配置字段。

### 读取行情

```http
GET /api/v1/earnings/market/2026-11-02/AAPL
Authorization: Bearer <existing backend key>
```

受现有鉴权保护，仅查询已采集数据，**GET 不会创建采集任务或触发抓价**。`date` 为财报的纽约日期，股票代码必须经过校验，非法输入返回 400。响应为：

```text
{ date, symbol, timeBasis: "first_detected_actual_eps", releaseTimeExact: false,
  observationStatus,
  tracking: { id, companyName, fiscalQuarterEnding, actualEps, detectedAt, endsAt,
              status, currency, lastAttemptAt, lastSuccessAt, lastError } | null,
  snapshots: [{ timestamp, firstQuoteAt, lastQuoteAt, price, open, high, low, close,
                provider: "yahoo", timestampBasis }],
  coverage: { minuteCount, expectedMinuteCount, missingMinuteCount, windowEnded } }
```

`observationStatus` 区分 `not_observed`、`watching`、`tracking`、`already_reported`、`missed_after_gap`、`quarter_changed`。分钟桶可能从触发所在分钟开始，但 `firstQuoteAt` / `lastQuoteAt` 保留桶内真实采样时间，桶内不混入触发前报价。当前没有完整的公布前股价基线，因此不据此伪造相对公司公布时刻的涨跌或利好/利空结论。

### 客户端个股行情展示

- 周日程、月历日期展开和财报列表的财报卡片均提供“查看对应股价”，携带准确的纽约财报日与代码查询上述只读接口。全屏详情关闭后保留原日历日期、搜索、筛选和滚动位置。
- 展示最新存储采样价与币种、来源报价时间、检测/结束时间、采样走势、检测后 1/5/15/30/60 分钟的价格与变化，以及可拖动的 0–60 分钟股价反应时间线。所有涨跌幅相对**首个采样的 open**，并展示该基准价格和时间；不称为相对公司公布前的涨跌幅。
- 时点价格只使用目标时点前 90 秒内已存储的真实 open/close 观测，不选取目标之后的分钟 close、不插值、不拿最新价填补缺失时点。未到达的时点与无合格观测的时点均显示空值。曲线按真实报价时间定位，缺失分钟不跨空缺连线；同一报价时间的价格修正展示最新 close，但保留最初采样基准。
- 明确区分等待 EPS、首次观察时已公布、错过检测、未观察、正在采集、窗口结束、无有效采样等状态。窗口结束仍展示实际分钟覆盖及缺失数量，不能将 completed 视为数据完整。
- 页面可见且应用在前台时查询，活动任务和今天/昨天的待观察记录每 15 秒刷新；关闭页面或进入后台即取消，已结束窗口不持续轮询。刷新失败保留上次加载数据并明确标为旧数据；换模式/后端地址会先清除原来源的内容，迟到结果不能覆盖新来源。
- 直连模式明确提示需要后端模式，不根据当前报价伪造历史采集。旧后端 404/501 显示“请先更新后端”，401/403 显示鉴权问题，429 提示稍后重试；这些错误均停止自动重试。请求携带现有 Key/设备标识，并禁用 HTTP 缓存，手动刷新只读取数据，既不重启也不延长采集。
- 历史采样展示无需额外配置或依赖；实际使用需同步部署含 `earningsMarket` 接口及迁移 024 的后端。收藏另需客户端 schema 11，当前价需后端 `earningsQuote` 能力（见上文）。英/简中/繁中均有对应文案。

## Telegram 财报 API 诊断

管理员私聊发送 `/test_earnings_api [YYYY-MM-DD] [股票代码]`，默认纽约今天与 `AAPL`，通过按钮分别测试 Nasdaq 财报、TradingView 财报和公司 Logo。也可以从原 `/test_calendar_api` 菜单进入默认财报测试；新命令已加入机器人命令菜单与 `/help`。

- 日期支持纽约今天前 120 天至后 60 天，股票代码只接受经过校验的代码，不接受 URL 或路径。TradingView 仅测试今天及未来的下一期快照，历史日期不会发起请求。
- 使用运行中的同一个 `EarningsService` / `CompanyLogoService`，因此代理路由、请求串行化及 403/429 冷却与生产请求一致，不额外创建能绕过冷却的诊断客户端。Nasdaq/TradingView 同源同日期测试至少间隔 60 秒；Logo 测试全局至少间隔 60 秒，间隔记录在缓存目录 `probe.json`，重启仍保留。
- 每次独立请求所选上游，不使用日历缓存、磁盘旧 Logo 或其他源的成功结果掩盖失败；不写财报快照、不覆盖缓存 PNG，也不重置后台健康计数。仅更新必要的限流/诊断间隔状态。
- 回复显示纽约请求日期、直连/代理、HTTP 状态、响应格式、`rCode`、`data`/`rows` 类型和数量、规范化 `asOf`、`totalCount` 等白名单证据。Logo 显示 HTTP、MIME、PNG 校验、字节数与尺寸。JSON 上限 2 MiB，PNG 上限仍为 256 KiB；单次上游请求最长 10 秒。
- 有效空数组或合法 `rows:null` 可以显示 `validated_rows=0`；`data:null`、字段缺失、错日期、HTML 和截断仍判失败，不推断为空日。日期数据缺失也不等于全源断网，需结合请求日期和上游覆盖范围判断。
- 后台健康错误同样附带请求日期与响应结构。连续失败次数按实际日期请求累计，而不是按小时；本次未改变告警阈值或把结构异常降格为成功。
- 测试只对白名单管理员的本人私聊开放，先确认 Telegram 回调再等待上游，结果编辑原消息；不回显原始响应正文、上游任意消息、请求 URL、代理凭据或服务器真实配置。

Telegram 诊断本身仅需更新后端，不需要更新 APP；不改配置模板，不单独增加数据库迁移。上文个股行情采集另需迁移 024。
